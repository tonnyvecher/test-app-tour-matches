## Решения

В «Предстоящие» попадают только `scheduled`, в «Завершённые» — только `finished`.
`live` и `postponed` доступны в «Все»: они не являются ни будущими, ни завершёнными.

Для перенесённого матча с `startsAt: null` показываю «Дата уточняется». Нулевой счёт
не считаю отсутствующим, live-матчу показываю текущую минуту, а неизвестному статусу —
нейтральный текст. Дату форматирую без явного `timeZone`, поэтому используется пояс
устройства. Исходный `MATCHES_URL` содержал `OWNER/REPO`, поэтому подставил адрес
текущего публичного репозитория и отдельно проверил ответ сервера.

## Баги из части 2

1. Звёздочки: `Boolean(indexOf(id))` давал `true` для `-1` (элемент не найден) и
   `false` для индекса `0`. Кроме того, хук менял исходный массив через `push/splice`
   и передавал React ту же ссылку, поэтому обновление могло не вызвать рендер. Заменил
   проверку на `includes`, а изменение — на функциональный `setState` с новым массивом.
2. «Обновлено N сек назад»: эффект с пустыми зависимостями захватывал начальный
   `seconds`, поэтому каждый тик снова записывал одно и то же значение; `since` вообще
   не участвовал в расчёте, а интервал не очищался. Теперь значение считается как
   разница `Date.now()` и `since`, эффект перезапускается при обновлении и очищает таймер.

## Как я использовал ИИ

Использовал Codex для анализа репозитория, реализации и проверок. Результат проверил
через `npm run typecheck`, запуск `npm run web`, HTTP-ответ dev-сервера и успешную
сборку JS-бандла Metro; URL данных проверил отдельно.

Первый автоматический запуск `npm ci` оказался неполным: npm не создал `.bin` и
завис на сетевых сбросах. Это обнаружил не по отсутствию ошибки, а проверкой файлов
и запуском typecheck; затем установил зависимости через имеющийся Node 22.13,
соответствующий Expo SDK 57. Также не доверился комментарию, что URL уже готов:
увидел placeholder `OWNER/REPO` и проверил исправленный адрес реальным запросом.
